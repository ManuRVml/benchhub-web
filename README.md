# eco-comparator-web

React SPA for the Eco-Comparador (BencHUD) financial benchmarking tool. Presentation only; talks to `eco-comparator-bff` through a versioned HTTP contract.

Status: Phase 1 (design analysis) is done and Gate 1 is green; Phase 2 (scaffolding) is in progress. See
`docs/progress/STATUS.md`. Rules for agents and contributors: [AGENTS.md](./AGENTS.md).

## Requirements

- Node.js 24 (`engines.node >=24`, enforced by `engine-strict=true` in `.npmrc`).
- pnpm 11.9.0 (`packageManager` field; enable it with `corepack enable`).
- Git with the husky hooks installed by `pnpm install` (lint-staged on pre-commit, commitlint on commit-msg).
- The V2 prototype folder (`V2 _CUAN_ECO_Comparador 2`) for the prototype render checks.
- Later phases: podman, to run the BFF `-mock` container image for end-to-end tests.

## Start in 3 commands

```sh
pnpm install
pnpm verify
PROTOTYPE_DIR="../V2 _CUAN_ECO_Comparador 2" pnpm prototype:check
```

In PowerShell, set the variable first: `$env:PROTOTYPE_DIR = "..\V2 _CUAN_ECO_Comparador 2"`. From the repo checkout next
to the prototype folder, the default path already works and the variable can be left out.

## Environment variables

| Variable | Used by | Default |
| --- | --- | --- |
| `PROTOTYPE_DIR` | `pnpm prototype:render`, `pnpm prototype:check`, `pnpm gate:1` | `../V2 _CUAN_ECO_Comparador 2` (from the repo root) |
| `SYNTHESIS_PATH` | `pnpm gate:1` (synthesis hex check) | `../.plan/source-map/10-synthesis.md` |
| `SOURCE_ROOT` | `pnpm gate:1` (source coverage check) | the folder that holds the two prototype source folders |

The SPA itself has no environment variables yet; `.env.example` arrives with the app scaffold (P2-W01b).

## Scripts

| Script | What it does |
| --- | --- |
| `pnpm verify` | `pnpm lint && pnpm typecheck && pnpm test`; must be green before every delivery |
| `pnpm lint` / `pnpm lint:fix` | ESLint (`--max-warnings 0`), including the Feature-Sliced Design boundaries |
| `pnpm typecheck` | `tsc --noEmit` with the strict flags of `tsconfig.json` |
| `pnpm test` | Vitest (`--passWithNoTests` until the app has code) |
| `pnpm format` / `pnpm format:check` | Prettier write / check (`docs/` and `*.md` are ignored) |
| `pnpm check:architecture` | FSD boundaries, the ECharts import rule and the route-path rule only |
| `pnpm check:architecture:selftest` | Proves the architecture rules fail on the planted violations in `tools/arch-fixtures/` |
| `pnpm prototype:render` | Renders the prototype screens and overlays into `docs/design/screenshots/prototype/` |
| `pnpm prototype:check` | Validates the render manifest and re-renders a sample to prove it is stable |
| `pnpm gate:1` | Runs every Phase 1 checker and validates `docs/design/gate-1.md` |

Single checkers live in `tools/` and run with `node tools/<name>.mjs` (for example `node tools/check-agents-md.mjs`,
`node tools/check-design-consistency.mjs`). Each exits non-zero on failure.

## Where the design docs live

- `docs/design/screen-inventory/`: one file per screen (SCR-01..SCR-17); index `docs/design/screen-inventory.md`.
- `docs/design/view-data-contracts/`: one file per view, session, operation and command endpoint (the BFF's input);
  index `docs/design/view-data-contracts.md`. Both indexes are generated by `node tools/build-design-index.mjs`.
- `docs/design/`: design tokens, component catalogue, navigation map, overlays, conflicts, open questions, mock data
  catalogue, prototype screenshots and reference images.
- `docs/architecture/`: ADRs (`docs/architecture/adr/`), `tech-stack.md`, and developer guides:
  - `docs/architecture/design-system.md`: token pipeline, component layers, Storybook, accessibility
  - `docs/architecture/testing.md`: test pyramid, Vitest, Playwright, verification workflow
  - `docs/architecture/contract-workflow.md`: vendored contract, typed ports/adapters, contract generation
- `docs/progress/STATUS.md`: phase status.

## Working with eco-comparator-bff

The two repos are independent: separate clones, installs, pipelines and deployments. This repo never imports BFF code
(no relative paths, no workspace links). The only boundary is the contract:

1. A screen needs data → update its file in `docs/design/view-data-contracts/`.
2. The BFF implements it (Zod schemas → OpenAPI 3.1) and publishes a new `@eco/bff-contract` version.
3. This repo pins that version and regenerates types, Zod schemas and the client (`pnpm contract:generate` /
   `pnpm contract:check`, arriving in P3-13; ADR `docs/architecture/adr/0004-contract-consumption.md`).

For local end-to-end work, run the BFF `-mock` image with podman, or use the SPA's own mock adapters.
