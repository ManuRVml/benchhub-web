# i18n

Visible text always goes through i18n (AGENTS.md rule 15). Stack: i18next + react-i18next (exact pins in
`package.json`, see `docs/architecture/tech-stack.md`).

## Setup (`src/shared/i18n/`)

- One locale in v1: `es-CO`, which is also the fallback. There is no language detector; resources are bundled
  statically (`resources.ts` imports every JSON file), so initialisation is synchronous and the first render has its copy.
- Namespaces: `common` for the shell and copy shared by several screens, plus one per page slice, named after the
  folder in `src/pages/` (`login`, `access-gate`, `admin`, `home`, `analyses`, `analysis-definition`, `analysis-results`,
  `analysis-report`, `indicator-detail`, `value-monitor`, `sensitivities`, `presentations`, `presentation-detail`,
  `notifications`, `settings`, `forbidden`, `not-found`). Files: `src/shared/i18n/locales/es-CO/<namespace>.json`.
- Components call `const t = useT()`; code outside React imports `t`. Both come from `@/shared/i18n`.
- `i18next.d.ts` augments i18next's `CustomTypeOptions` with the resources, so an unknown key is a type error and editors
  autocomplete keys.

## Key convention

- Dot notation, with the namespace as the first segment: `t('common.nav.home')`, `t('home.peerNews.empty')`. Always
  write the namespace, even for `common`.
- Segments after the namespace are English camelCase and describe where the text lives, not what it says:
  `<namespace>.<section>.<element>` (for example `analyses.filters.searchPlaceholder`).
- Values are the Spanish copy quoted verbatim from the screen inventory (`docs/design/screen-inventory/`), which quotes
  the prototype. Interpolation uses i18next placeholders: the inventory's `{analysisName}` is written
  `{{analysisName}}`.
- Pass numbers, dates and units as raw values and format them with the es-CO formatters (ADR
  `docs/architecture/adr/0008-locale-formatting.md`); never build formatted numbers into translation strings.

## Guards

- ESLint `react/jsx-no-literals` (in `eslint.config.js`) rejects literal JSX text in `src/pages`, `src/widgets`,
  `src/features`, `src/entities` and `src/shared/ui`. Only punctuation and glyphs are allowed.
- `src/shared/i18n/i18n.test.ts` fails when a `t('…')` key used anywhere in `src/` is missing from the es-CO resources,
  or when a `common` value is not quoted verbatim in `SCR-04-app-shell.md`.
